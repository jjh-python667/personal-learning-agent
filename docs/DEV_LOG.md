# 开发日志

这里记录学习搭子每版遇到的问题、设计选择和验证过程。功能清单见 [版本记录](../CHANGELOG.md)，细节可以在 GitHub 的提交记录中查看。

## v0.1.0 · 先跑通一次完整学习

想解决的问题是资料和进度分散。第一版先跑通网页上传资料、在 QQ 查资料、按段学习和答题续接。网页与 QQ 接入同一个 Python 后端，SQLite 保存资料和进度。

调试时遇到过数据库里有资料、机器人却回复资料库为空。执行记录显示那次回复没有查资料。于是把明确的资料列表请求改成直接读数据库，并补上回归测试。

验证覆盖资料导入、题目状态、失败重试和暂停续接。本地 29 项测试通过。

## v0.2.0 · 把「连续对话」落实为分条发送

收到的反馈是聊天页需要改善，并且希望一次提问后能收到多条回复。讨论时先实现了答题后自动进入下一段。进一步确认后，连续回复的验收条件变成了网页出现独立气泡、QQ 分别发送两到三条消息。连学作为独立选项保留。

网页把对话和学习进度放到同一页。资料检索加入 SQLite 缓存，重复关键词可以复用，资料变动后会失效。执行记录能看到命中情况。

本地 38 项测试通过。浏览器确认一次提问后依次显示三个气泡，QQ 分次发送用模拟接口验证。网页截图见 [v0.2.0 发布页](https://github.com/jjh-python667/personal-learning-agent/releases/tag/v0.2.0)。

## v0.3.0 · 给课程和会话分清边界

同时学两门课时，资料、题目和聊天容易混在一起。现在按课程保存资料、任务和题目，按会话保存聊天和执行记录。同一门课下可以开多个会话继续使用已有学习进度。网页可以指定 QQ 继续哪个会话。

升级时把已有数据归到「默认课程 / 默认会话」。新增测试验证旧表迁移、课程内检索、会话历史分离、QQ 切换，以及答一门课的题不会推进另一门课。

本地 42 项测试通过。浏览器验证新建课程和会话、切换、刷新续接。真实 QQ 与模型的新版收发留待部署后验证。

## 后续怎么记

每次更新补充三件事：遇到了什么、为什么这样改、怎么确认改好了。失败复现和取舍也可以记录。遇到改动较大的一版，先用分支保存阶段性提交，再对照测试结果发布。
